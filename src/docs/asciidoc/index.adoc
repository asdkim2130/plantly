[[overview]]
== 개요

Plantly 서비스의 REST API 명세서입니다.
모든 응답은 아래 공통 래퍼(`ApiResponse`) 형태로 내려갑니다.

[[overview-response-wrapper]]
=== 공통 응답 형식

[cols="2,1,5"]
|===
| 필드 | 타입 | 설명

| `success` | `boolean` | 요청 성공 여부
| `message` | `string` | 성공 메시지 (성공 시, 없을 수 있음)
| `data`    | `object` | 응답 데이터 (성공 시, 없을 수 있음)
| `error`   | `string` | 에러 메시지 (실패 시에만 존재)
|===

NOTE: `ApiResponse` 는 `@JsonInclude(NON_NULL)` 이므로 값이 `null` 인 필드는 JSON 응답에서 생략됩니다.
예를 들어 회원가입 성공 응답에는 `data`/`error` 가 나타나지 않습니다.

[[overview-auth]]
=== 인증 / 보안 공통 규약

세션 기반 인증을 사용합니다. 인증 메커니즘은 전역 공통 규약이므로 각 API 문서에 반복하지 않고 여기에 한 번만 명시합니다.

* *로그인*: `POST /api/v1/auth/login` 성공 시 `JSESSIONID` 세션 쿠키가 발급됩니다.
  이후 인증이 필요한 요청에는 이 세션 쿠키가 자동으로 동봉되어야 합니다.
* *CSRF*: 상태를 변경하는 모든 요청(`POST`, `PATCH`, `PUT`, `DELETE`)은 CSRF 보호를 받습니다.
  먼저 `GET /api/v1/auth/csrf` 로 토큰을 발급받은 뒤, 발급된 값을 `X-XSRF-TOKEN` 요청 헤더에 담아 보내야 합니다.
  누락 시 `403` 이 반환됩니다.
* *인증 실패*: 미인증 상태로 보호 자원에 접근하면 `401`, 권한이 부족하면 `403` 이 반환됩니다.

[cols="2,1,5"]
|===
| 항목 | 위치 | 설명

| `JSESSIONID` | Cookie | 로그인 시 발급되는 세션 쿠키 (인증 필요 API 필수)
| `X-XSRF-TOKEN` | Header | CSRF 토큰 (변경 요청 필수)
|===

| 존재하지 않는 카테고리 ID | 존재하지 않는 카테고리가 포함되어 있습니다.
| 존재하지 않는 인증 ID | 존재하지 않는 인증이 포함되어 있습니다.
| 존재하지 않는 국가 ID | 존재하지 않는 국가가 포함되어 있습니다.
| 존재하지 않는 국내 지역 ID | 존재하지 않는 국내 지역이 포함되어 있습니다.
| 존재하지 않는 산업군 ID | 존재하지 않는 산업군이 포함되어 있습니다.
|===

[[company-search]]
=== 회사 목록/검색 (공개)

회사를 검색·브라우즈합니다. 누구에게나 열려 있는 공개 API 로, 인증이 필요 없습니다.

검색은 세 축으로 조합됩니다(모두 선택적, 지정한 것만 AND 로 적용):

* *통합 키워드* (`keyword`): 회사명·소개·레퍼런스·설비·소재 등 전체 텍스트에 부분일치. 공백으로 나눈 여러 토큰은 모두 포함(AND).
* *고급검색* (`companyName`/`content`/`reference` 등): 지정한 필드에만 부분일치.
* *패싯* (`certificationIds`/`industryIds`/`categoryIds`): 선택한 ID 중 하나라도 보유한 회사(차원 내 OR). 카테고리는 대분류를 고르면 그 후손 서브트리까지 매칭됩니다.

정렬은 스팟라이트 → 추천 → 최신 순으로 고정이며, 결과는 요약 카드 형태로 페이징됩니다.

[[company-update]]
=== 회사 기본 정보 수정 (소유자)

회사 멤버 본인이 자기 회사의 기본 정보를 부분 수정합니다. 변경 요청이므로 세션 쿠키와 CSRF 토큰이 필요합니다(<<overview-auth>> 참고).

본체 스칼라 필드만 수정하며, 부속 컬렉션(태그·소재·설비·연락처·이미지·레퍼런스·링크 마스터)은 <<company-update-collections>> 로 따로 교체합니다.

* *부분 수정(sparse)*: 모든 필드가 선택이며, 요청에 담긴 필드만 변경됩니다(`null`/미포함 = 미변경).
* *비우기(clear) 규약*: 선택 문자열 필드는 빈 문자열(`""`)을 보내면 값을 비웁니다. 필수 필드(회사명·대표자·주소 등)는 빈 문자열로 비울 수 없어 `400` 이 반환됩니다. 날짜·enum 은 비우기를 지원하지 않습니다(값이 오면 교체만).
* 시스템 플래그(`verified`/`featured`/`spotlight`/`spotlightOrder`/`deleted`)·사업자번호·등록 provenance 는 이 API 로 바꿀 수 없습니다(요청 필드에서 제외).

수정 값은 이미 화면에 반영되어 있으므로, 성공 응답은 본문 없이 `success` 플래그만 내려갑니다.

| `PUT /api/v1/companies/{id}/materials` | `["문자열", ...]` | 취급 소재명 목록
| `PUT /api/v1/companies/{id}/equipment` | `["문자열", ...]` | 보유 설비명 목록

[[admin-company-list]]
=== 회사 목록 (관리자)

관리자가 전체 회사를 목록으로 조회합니다. 기본은 *삭제된 회사까지 포함한 전체* 이며, 최신 등록순으로 페이징됩니다.
공개 목록과 달리 각 카드에 운영 필드(삭제 여부·소유자 id·등록 출처·등록 시각)와 구독 요약이 함께 내려갑니다.

구독 요약은 *지금 유효한 등급*(`effectiveGrade`) + *상태*(`status`) + *만료일*(`expiresAt`) 3종입니다.
`status` 로 체험(`TRIAL`)·결제(`ACTIVE`)·면제(`ADMIN_EXEMPT`)를 목록에서 바로 구분할 수 있습니다.
`effectiveGrade` 는 만료된 유료 구독을 `FREE` 로 강등한 "현재 실제 적용 등급"이며, 계약 원본 등급은 목록에 싣지 않고 구독 수정(<<admin-company-subscription>>)에서 다룹니다.

다음 조건으로 좁힐 수 있으며, *지정한 것만 AND(교집합)* 로 적용됩니다(미지정 = 상관없음):

* *상태 필터* (`verified`/`featured`/`spotlight`): `true`/`false` 로 해당 값만. 생략하면 그 축은 무시됩니다. 예) `verified=true&featured=true` 면 둘 다 참인 회사만(스팟라이트는 무관).
* *삭제 필터* (`deleted`): 생략하면 삭제 포함 전체, `true` 면 삭제된 회사만, `false` 면 활성 회사만.
* *회사명* (`companyName`): 부분일치.
* *소유자* (`ownerUserId`): 소유 유저 ID 정확 일치(미연동 회사는 제외됨).

[[admin-company-subscription]]
=== 회사 구독 조회/수정 (관리자)

관리자가 임의 회사의 구독을 조회하고 수정합니다. 소유 여부와 무관하게 모든 회사를 대상으로 하며, `ADMIN` 권한이 필요합니다(<<overview-auth>> 참고).
구독의 주인은 회사(1:1)이므로 구독 관리도 회사 단위로 이뤄집니다 — 목록에서는 파생 등급 배지만 노출하고, 배지 옆 수정 버튼으로 이 조회/수정을 띄우는 흐름을 상정합니다.

조회 응답에는 사용자용 구독 조회(<<company-subscription>>)와 같은 필드에 더해 감사용 타임스탬프(`createdAt`/`updatedAt`)가 포함됩니다.

수정은 `grade`/`status`/`expiresAt` 세 필드를 관리자가 직접 지정하는 *전체 교체(full-replace)* 입니다. 수정 팝업이 세 필드를 항상 채워 보내는 것을 전제로 합니다.

* `grade`/`status` 는 필수입니다.
* `expiresAt` 은 만료일이며, `null` 이면 *무기한*(만료 없음)을 뜻합니다.
* `startedAt`(시작일)은 팩트라 수정 대상이 아닙니다(기존값 보존).
* `effectiveGrade`(지금 유효한 등급)는 `grade`/`status`/`expiresAt` 에서 파생되므로 별도로 저장·수정하지 않습니다. 예를 들어 유료 등급이라도 `expiresAt` 이 과거이면 조회 시 `effectiveGrade` 는 `FREE` 로 내려갑니다.

NOTE: 이 API 는 구독 테이블만 변경합니다. 등급을 낮춰도 이미 초과된 기존 데이터(카테고리 수 등)를 소급해서 잘라내지 않으며, 해당 컬렉션을 다음에 수정하는 시점에 등급 정책이 적용됩니다.

# 국세청 사업자 인증 — 비즈니스 정책 요약

- **작성일:** 2026-07-21
- **대상 독자:** 비개발자 (기획·운영·정책 담당)
- **목적:** 국세청 사업자 인증과 관련해 지금까지 결정한 정책들을 한눈에 보고, 각자 정리한 내용과 대조하기 위한 문서
- **표기:** ✅ 현재 적용 중 · 🔜 방향만 정하고 예정·보류

> 이 문서는 "무엇을 왜 이렇게 하기로 했나"(정책)만 담았습니다. 화면 문구·개발 방식은 제외했습니다.

---

## 1. 회사를 등록할 때

| 상태 | 내용 |
|---|---|
| ✅ | **일반 회원이 직접 회사를 등록할 땐 국세청 인증이 필수**입니다. |
| ✅ | **관리자가 대신 등록하는 회사는 인증 없이도 가능**합니다. (검색 노출용 임시/씨앗 데이터 성격) |
| ✅ | 인증은 **회사 정보를 다 채우기 전에 먼저** 합니다. (아이디 중복확인처럼 — 정보 다 입력한 뒤 마지막에 튕기는 걸 막기 위해) |
| ✅ | 인증으로 확인된 값(**사업자번호·대표자명·개업일자**)은 사용자가 임의로 바꿀 수 없습니다. 시스템이 국세청 결과로만 채웁니다. |
| ✅ | **폐업·휴업한 사업자는 등록할 수 없습니다.** (번호가 진짜인지만 보면 폐업자를 못 거르므로 영업 상태까지 확인) |
| ✅ | 기준 날짜는 **개업일자**입니다. (법인 설립일이 아니라 사업자등록증상 개업일 — 국세청이 이 날짜로만 대조함) |

---

## 2. 남용 방지

| 상태 | 내용 |
|---|---|
| ✅ | 인증은 받은 뒤 **7일간 유효**하고, **한 번 등록에 쓰면 재사용할 수 없습니다.** (기간은 설정값 `app.verification.ttl`) |
| ✅ | 유효기간이 지나도 **등록이 막히지는 않습니다.** 저장 버튼을 누르면 서버가 저장된 값 그대로 국세청에 다시 물어보고(자동 재질의), 여전히 통과하면 조용히 갱신한 뒤 그대로 등록합니다. |
| — | *이유:* 만료의 목적은 "그 사이 폐업했는지"를 다시 보는 것이지 사용자가 쓰던 글을 버리게 하는 것이 아닙니다. 기간을 짧게 잡아도 막히는 사고는 거의 없고, 폼을 오래 붙들고 있던 정상 사용자만 걸립니다. |
| ✅ | 만료가 사용자에게 드러나는 경우는 **국세청이 실제로 다른 답을 줬을 때뿐**입니다. (폐업·휴업·정보 불일치 — 이때는 정말 등록을 막아야 하는 상태) |
| ✅ | **하루 인증 시도는 5회로 제한**합니다. (무단 추측·국세청 호출 낭비 방지 — 설정값 `app.verification.daily-attempt-limit`) |
| ✅ | 단, **국세청 시스템 장애로 실패한 건은 횟수에서 차감하지 않습니다.** (우리 탓이 아닌 실패로 하루치 기회를 잃지 않도록) |
| ✅ | **자동 재질의도 횟수에서 차감하지 않습니다.** (사용자가 누른 적 없는 호출이라 — 차감하면 "가만히 있었는데 오늘 인증을 다 썼다"가 됩니다) |

## 3. 두 종류의 "인증 배지" 구분

| 상태 | 내용 |
|---|---|
| ✅ | **"에디터 선정"(관리자 큐레이션 배지)** 과 **"국세청 사업자 확인"(진위 인증)** 은 **완전히 다른 것**으로 분리했습니다. |
| — | *이유:* 하나로 합치면 관리자가 추천 배지를 켜다가 실수로 사업자 인증 자격까지 부여하는 사고가 날 수 있어서입니다. |

---

## 4. 사업자번호 관리

| 상태 | 내용 |
|---|---|
| ✅ | 사업자번호는 **현재 운영 중인(삭제되지 않은) 회사끼리만** 겹치면 안 됩니다. |
| ✅ | **삭제된 회사가 쓰던 번호는 다시 사용할 수 있습니다.** |
| ✅ | **관리자가 인증을 회수**할 수 있습니다. (사칭 신고 등) 이때 **회수 사유는 필수**입니다. |
| ✅ | 인증을 회수해도 **사업자번호는 지우지 않습니다.** (같은 번호로 다시 등록하는 걸 막고, 분쟁 대응 기록으로 남기기 위해) |

---

## 5. 정보 변경 · 재인증

| 상태 | 내용 |
|---|---|
| ✅ | 인증받은 회사가 **대표자명·개업일자를 바꾸려면 "재인증"을 거쳐야만** 합니다. |
| — | *이유:* 그냥 수정하게 두면, 인증을 통과한 뒤 아무 값으로 바꿔놓고도 "국세청 확인" 배지를 유지할 수 있어서입니다. |
| ✅ | 재인증할 때 **사업자번호는 새로 입력받지 않고, 저장된 값을 그대로 씁니다.** (다른 회사 번호로 갈아끼워 배지를 가로채는 걸 원천 차단) |
| ✅ | 국세청 정보가 바뀌었을 수 있으므로, 재인증은 **이전 값과 비교하지 않고 새로 입력한 값이 통과하면 갱신**합니다. |
| ✅ | **인증을 받지 않은 회사**(관리자 등록 등)는 대표자명·개업일자를 **자유롭게 수정할 수 있습니다.** |
| 🔜 | **최초 인증 후 1년이 지나면 재인증을 유도**합니다. (자동 알림 기능은 나중에, 지금은 수동으로 재인증하는 창구만 열려 있음) |

---

## 6. 관리자 등록 회사 처리 *(최근 결정)*

| 상태 | 내용 |
|---|---|
| ✅ | 관리자가 등록해 둔 회사를 **일반 회원이 넘겨받는 "인수(클레임)" 절차는 만들지 않기로** 했습니다. |
| ✅ | 대신 **회원이 자기 사업자번호로 새로 등록**하고, 중복되는 관리자 등록본은 **관리자가 정리(삭제)** 합니다. |
| — | *이유:* 씨앗 데이터는 사업자번호가 없어 "이 회사가 내 것"임을 인증만으로 증명할 수 없습니다(탈취 위험). 새로 등록하면 이 문제가 아예 사라집니다. |
| 🔜 | **비슷한 회사 중복을 자동으로 걸러내는 기능은 지금은 하지 않습니다.** (관리자 등록이 약 150건으로 적어서) |
| 🔜 | **관리자 등록이 크게 늘어나면 그때 중복 정리 기능을 검토**합니다. |

## 7. 방향만 정하고 미룬 것

| 상태 | 내용 |
|---|---|
| 🔜 | **증빙서류 제출 + 관리자 검토** 단계는 로드맵상 뒤로 둡니다. |
| 🔜 | **가입 첫 달 혜택** 등 혜택 정책은 뒤 단계로 둡니다. |
| 🔜 | 혜택을 붙일 땐 **사업자번호를 기준으로 수령 이력을 관리**하기로 방향을 잡았습니다. (회사를 지웠다 같은 번호로 다시 만들어 혜택을 반복 수령하는 걸 막기 위해) |
